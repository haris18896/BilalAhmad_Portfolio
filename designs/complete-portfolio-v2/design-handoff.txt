VISUAL SYSTEM
Background: warm ivory #F5F2EB. Text: charcoal #232420.
Accent: terracotta #AE5840. Rules: muted warm grey #B9B6AE.
These are target tokens; generated pixels may differ slightly.
Primary typography: strong contemporary sans serif, proposed Manrope.
Editorial accent: restrained serif, proposed Cormorant Garamond.
Decorative micro-labels: sans serif, small uppercase with careful letter spacing.
Avoid handwritten quotes as a dominant brand element.
Headlines desktop 72-112px, mobile 44-56px; section headings 32-48px.
Body desktop 18px, mobile 16px minimum, line-height 1.5-1.65.
Small interface labels minimum 14px in the implementation.
Desktop: 12-column grid, max content width 1440px, 64px outer gutters.
Tablet: 32px gutters. Mobile: 20px gutters, mostly a single column.
Spacing steps: 8 / 16 / 24 / 32 / 48 / 64 / 96 / 128px.
Square image edges, delicate rules, understated outline buttons.
Consistent image ratios within each grid row; preserve drawing legibility.
Do not crop technical plans to fill photographic image ratios.
Buttons and controls have at least 44px touch targets.
Use actual source photos/renders in the final site, not mockup extractions.

MOTION SPECIFICATION
Motion is a proposed behavior specification; the PNGs and PDF are static.
Use natural ease-out cubic-bezier(0.22, 1, 0.36, 1).
Hero text: line mask reveal, translateY 24px to 0, 650ms, 70ms line stagger.
Portrait: opacity 0 to 1 with translateY 12px, 700ms, starts after 200ms.
Hero never blocks scrolling, navigation, or access to content.
Section entry: opacity and translateY 16px, 450ms, once on entering viewport.
Project images: subtle clipped reveal, 600ms; final geometry stays unchanged.
Project hover: image scale 1 to 1.025, arrow moves 4px, 250ms.
Keyboard focus receives the same clear border/arrow emphasis without zoom.
Category change: 180ms fade, subtle layout transition up to 250ms.
Preserve filter state in the URL and retain focus on the selected filter.
Page transition: optional 180ms content fade; no long intro or scroll hijack.
Lightbox: 200ms fade; image crossfade 150ms, no elastic zoom.
Mobile menu: 300ms fade and translateY 8px, links stagger 35ms.
Active nav underline: 200ms width transition.
Enquiry button: clear idle / sending / success / error states.
Success appears only after the delivery service confirms receipt.
No indefinite autoplay, 3D tilt, custom cursor, pinned horizontal scroll or
essential information revealed only through animation.
Reduced motion: remove transforms, scaling and stagger; use immediate content
or brief 100ms fades. Content remains readable if animation scripts fail.
Use normal browser scrolling. Any optional scroll smoothing respects reduced
motion and keyboard navigation and is not required for the design.
No new generated video is required. Optional supplied project clips can be
user-initiated media in case studies with a poster and playback controls.

INTERACTION AND ACCESSIBILITY
Project title/card links have descriptive accessible names.
Gallery uses original images; technical drawings open without destructive crop.
Lightbox supports Escape, arrow keys, focus trap and return to trigger focus.
Menu supports Escape, focus trap, scroll lock and focus return.
Filters have an obvious active state beyond color and readable text.
Form: name, email, project interest, message; clear labels and inline errors.
Announce sending/success/failure using accessible status messages.
Never clear an enquiry after failed delivery; retain the visitor's entries.
External links and PDF links communicate their destination clearly.
Text contrast is checked on actual tokens; terracotta is not used for small
low-contrast body text. Avoid text over busy imagery unless contrast is ensured.
Missing images get a reserved-size neutral fallback; project titles stay usable.

EDITOR WORKFLOW
1. Open Studio and create a Project.
2. Enter title, discipline, summary and an automatically suggested unique slug.
3. Upload cover, gallery images, drawings, PDFs and optional video.
4. Add captions, accessible descriptions, credit/role and optional story sections.
5. Preview, optionally mark Featured, choose order and publish.
6. Site queries pick up the published project without editing UI code.
For the implementation: target public content refresh within 60 seconds after
publishing. Webhook revalidation can later reduce that delay.
The delay is a future acceptance criterion, not a verified current integration.
Preview should expose drafts only to authenticated editors.
Editing/adding projects requires a logged-in Studio, not a browser write token.
